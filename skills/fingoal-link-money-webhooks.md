# Manage Link Money webhooks

Unlike the Insights API — where the legacy enrichment callback is registered by
emailing support — Link Money webhooks are fully self-service.

## 1. Authenticate

`oauthToken` — POST `/api/oauth/token` with `{ clientId, clientSecret, tenantId }`.
Send the returned `token` as `Authorization: Bearer <token>`. It expires after 1
hour and covers a single tenant, so webhooks are managed per tenant.

## 2. List what is registered

`getWebhooks` — GET `/client/webhooks`.

## 3. Register a callback

`createWebhook` — POST `/client/webhooks` with:

- `uri` — must match `^https:\/\/`. Plain HTTP is rejected.
- `webhookTypes[]` — any of `DATA_UPDATES`, `REFRESH`, `AUTO_REFRESH_UPDATES`,
  `LATEST_BALANCE_UPDATES`, `CDV_STATUS_UPDATES`, `OB_CONSENT`,
  `OB_ACTIVE_CONSENT_REMINDER`.
- `webhookDisabled` — optional boolean.

Returns `201` with the `Webhook` object; `id` is a UUID generated by Link Money.

## 4. Test before you trust it

`fireTestWebhook` — POST `/client/webhooks/{webhookId}/fire_test_webhook` sends a
dummy payload to the registered `uri` and reports back `receivedResponse`,
`responseCode` and `firedAt`. Run this at deploy time, not just at integration
time — it is the cheapest way to catch a callback that a firewall change broke.

## 5. Watch delivery health

`getWebhook` — GET `/client/webhooks/{webhookId}` returns health fields Link
Money maintains for you:

- `status` — `HEALTHY`, `UNHEALTHY`, or null if never attempted.
- `lastAttempt` / `lastAttemptStatus` — when Link Money last tried, and the HTTP
  code your endpoint returned.
- `lastSuccess` — when it last got a 2XX.

This is worth polling on a schedule: it tells you your own receiver is failing
without any instrumentation on your side.

## 6. Change or remove

- `updateWebhook` — PATCH `/client/webhooks/{webhookId}` to change the `uri`,
  the `webhookTypes[]`, or to flip `webhookDisabled`. Prefer disabling over
  deleting during an incident so the registration and its history survive.
- `deleteWebhook` — DELETE `/client/webhooks/{webhookId}`.

## Rules

- Payload schemas for the individual event types are **not** published in the
  Link Money OpenAPI — only the event names. Do not assume a shape; fire a test
  webhook and record what actually arrives.
- FinGoal's developer FAQ calls webhooks optional but recommended, with
  `DATA_UPDATES` as the event most integrations need.
- See `asyncapi/fingoal-link-money-webhooks.yml` for the full event catalog and
  `conventions/fingoal-conventions.yml` for how Link Money differs from the
  Insights API.
